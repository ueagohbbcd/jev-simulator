# 增强模式与配置方向

2026-09-28，工作方向；后续项是候选，不是已实现功能。

配置按输出读取、提示词、比较方式和概率后处理组织，各项声明依赖、互斥和执行顺序。方法的效果通过实验评估。

## 使用方式

主要用法是由部署者在本地 TOML 中选择上游和推理方法，启动服务，再让应用调用兼容端点 `/v1/systemone`。提示词、概率读取和比较策略由服务执行，应用使用统一的判断、分类和评分结果。配置可通过终端热重载，预览和诊断可通过 CLI 完成。

`/v1/evaluate` 是逐请求指定推理配置的可选入口，适用于远程实验或需要动态选择方法的应用。它不保存配置或修改服务默认值。服务提供可选 Bearer 鉴权，不承担多用户、额度结算和远程配置管理。

## 执行边界

```text
System One 请求 + 完整配置快照
  -> 校验组合和调用预算
  -> 制定调用计划（逐题、比较、标签映射）
  -> 渲染提示词、调用模型、读取原始结果
  -> 映射回语义、聚合、后处理
  -> 兼容答案 + 独立诊断
```

预设以完整 TOML 文件提供。CLI 的 preview 展开调用计划，evaluate 执行调用并可保存诊断。生成温度与概率后处理温度分别配置。

## 当前实现

- 增加 `adapter.mode = "reported_probability"`，默认仍为 `token_logprobs`。两种读取模式互斥；新模式读取模型生成的 JSON 数值分布，不要求 logprobs。
- 新模式先沿用每题／每比较分支一次调用，支持 Noul、Choice、Score，并与现有双循环、呼号、后处理温度组合。保持先逐分支温度变换、再聚合的顺序。
- 提示词可直接编辑，提供完整示例配置；JSON 输出协议由 `{{output}}` 展开。校验标签完整性、数值范围、总和与完成状态，错误不自动变成均匀概率或触发付费重试。
- 诊断保留原始报告、语义映射、变换前后分布与有效模式；数值报告不包含 token 概率质量。兼容端点的响应形状保持不变。

直接报告概率的前期实验采用多题共同回答，同时改变了提示词和生成参数；当前实现逐题调用，其效果需要另行评估。

扩展端点的 `dry_run` 与实际执行共用配置校验和调用计划，详见 [API](api.md)。

图片输入采用兼容端点的可选顶层 `images`，扩展端点复用同一请求结构；内联 base64／data URL，经本地校验后转为原生视觉消息。不新增上传端点、不解释普通 state 内的链接；服务端显式声明上游图片能力。

## 后续按实验推进

1. 显式支持问题分组：独立回答／共同回答。需要共同规划输出映射、预算和用量，避免重复记账；比较共同回答与逐题回答的结果。
2. 增加标签映射交换、重复与聚合选项。通过实验选择需要支持的组合。
3. 当前图片路径直接交给视觉上游；先提取文本、其他模态和更细的图片布局仍为候选。

评估分别报告结果误差、一致性、重复波动、失败率、成本和延迟，不把某个指标的改善当作所有用途都改善。双循环输出仍是归一化胜分；配置中明确执行含义。
