# 增强模式与配置方向

2026-09-28，工作方向；后续项是候选，不是已实现功能。

项目提供改善决策结果的各种手段：输出读取模式、提示词、比较赛制、重复、聚合与后处理。交互不按“提高准确率／改善概率校准”分区；按作用位置组织，声明互斥、依赖和组合顺序。提示词就是模板中的可编辑文本。

## 执行边界

```text
System One 请求 + 完整配置快照
  -> 校验组合和调用预算
  -> 制定调用计划（逐题、比较、标签映射）
  -> 渲染提示词、调用模型、读取原始结果
  -> 映射回语义、聚合、后处理
  -> 兼容答案 + 独立诊断
```

保留现有 preview、evaluate、配置 ID 与热重载。预设首先是一份可编辑的完整 TOML，不增加隐藏执行逻辑。只拒绝无法执行的组合；效果未知但合法的组合可供实验。生成温度与概率后处理温度分别命名。

## 当前实现

- 增加 `adapter.mode = "reported_probability"`，默认仍为 `token_logprobs`。两种读取模式互斥；新模式读取模型生成的 JSON 数值分布，不要求 logprobs。
- 新模式先沿用每题／每比较分支一次调用，支持 Noul、Choice、Score，并与现有双循环、呼号、后处理温度组合。保持先逐分支温度变换、再聚合的顺序。
- 提示词可直接编辑，提供完整示例配置；JSON 输出协议由 `{{output}}` 展开。校验标签完整性、数值范围、总和与完成状态，错误不自动变成均匀概率或触发付费重试。
- 诊断保留原始报告、语义映射、变换前后分布与有效模式；不为数值报告伪造 token 概率质量。HTTP 响应形状保持不变。

新增实验中，直接报告概率在 33 道明文题上准确，13 道半衰期题 MAE 为 0.00924 个百分点。但实验一次共同回答正反 Noul 和 Choice，也改变了提示词、生成参数；第一轮每题独立的通用实现不宣称复现该效果。

请求级交互已收敛并实现为一个扩展端点 `POST /v1/evaluate`：每次携带推理配置，`dry_run` 共用校验和计划；不使用服务端 profile，也不新增 preview/capabilities 端点。兼容端点继续使用服务默认配置。详见 [API](api.md)。

图片输入采用兼容端点的可选顶层 `images`，扩展端点复用同一请求结构；内联 base64／data URL，经本地校验后转为原生视觉消息。不新增上传端点、不解释普通 state 内的链接；服务端显式声明上游图片能力。

## 后续按实验推进

1. 显式支持问题分组：独立回答／共同回答。需要共同规划输出映射、预算和用量，避免重复记账；再比较与第一轮的结果。
2. 增加标签映射交换、重复与聚合选项。先验证具体组合，再抽取共享代码，不先建设通用插件框架。
3. 当前图片路径直接交给视觉上游；先提取文本、其他模态和更细的图片布局仍为候选。

评估分别报告结果误差、一致性、重复波动、失败率、成本和延迟，不把某个指标的改善当作所有用途都改善。双循环输出仍是归一化胜分；配置中明确执行含义。
